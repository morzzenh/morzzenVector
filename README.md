# morzzenVector: RAG-система (семантический поиск)

**morzzenVector** — это локальная RAG-система (Retrieval-Augmented Generation) для семантического поиска по текстовым документам. 

Проект реализует полный цикл работы с данными: **загрузка файла → извлечение и разбиение текста на чанки → создание эмбеддингов (через локальные модели Ollama) → сохранение векторов в PostgreSQL (pgvector) → гибридный поиск по смыслу.**

Работает полностью автономно: не требует API-ключей, платных подписок и сторонних облачных сервисов.

## Преимущества проекта

* **Полностью локальная работа:** Модель `bge-m3` разворачивается через Ollama прямо в Docker. Никаких затрат на OpenAI или другие API.
* **Привычная база данных:** Используется стандартный PostgreSQL с расширением `pgvector`. Не нужно поднимать отдельные векторные БД.
* **Асинхронность:** Код полностью асинхронный (`async/await`) от чтения и парсинга файла до записи в базу данных и поиска.
* **Строгая валидация:** Все входящие данные (запросы, файлы, параметры) проверяются через Pydantic и встроенные механизмы FastAPI.
* **Расширяемость:** Чистая архитектура (роутеры, сервисы, репозитории) позволяет легко добавить новые форматы файлов, другие модели эмбеддингов или изменить логику чанкирования.

## Стек технологий

* **Backend:** Python 3.14, FastAPI, Pydantic, LangChain
* **База данных:** PostgreSQL 18 + `pgvector`
* **ORM и миграции:** SQLAlchemy (async), Alembic
* **AI / RAG:** Ollama (модель `bge-m3`)
* **Инфраструктура:** Docker, Docker Compose, `uv` (менеджер пакетов)

## Архитектура

Проект упакован в 5 Docker-контейнеров, которые запускаются одной командой:
1. **`database`** — PostgreSQL с установленным расширением `pgvector` для хранения векторов.
2. **`ollama`** — сервер с локальной нейросетью для генерации эмбеддингов.
3. **`ollama-model-loader`** — одноразовый контейнер, который скачивает нужную модель (по умолчанию `bge-m3`) и загружает её в Ollama.
4. **`migrations`** — одноразовый контейнер, который применяет миграции Alembic к базе данных перед запуском API.
5. **`api`** — само FastAPI-приложение.

## Быстрый старт

### 1. Требования
Убедитесь, что у вас установлены [Docker](https://docs.docker.com/get-docker/) и [Docker Compose](https://docs.docker.com/compose/install/).

### 2. Настройка окружения
Скопируйте пример конфигурации и заполните необходимые переменные (особенно доступы к БД):
```bash
cp .env.example .env
```
*(Откройте `.env` и укажите `DATABASE_USER`, `DATABASE_PASSWORD` и `DATABASE_NAME`)*.

### 3. Запуск проекта
Запустите сборку и старт всех контейнеров:
```bash
docker-compose up --build
```
*При первом запуске потребуется время, чтобы скачать образы, собрать приложение и загрузить модель эмбеддинга в Ollama.*

### 4. Проверка работы
После успешного запуска откройте интерактивную документацию (Swagger UI) в браузере:
👉 **[http://localhost:8000/docs](http://localhost:8000/docs)**

Здесь вы можете протестировать загрузку файлов и поиск прямо из браузера.

## API Эндпоинты

### 📥 `POST /uploadfile`
Загрузка одного или нескольких текстовых документов.
* **Что делает:** Проверяет тип и размер файла, защищает от дубликатов (через хэш SHA-256), разбивает текст на чанки, векторизует их и сохраняет в БД.
* **Ошибки:** Возвращает `415` (неподдерживаемый формат), `413` (файл слишком большой), `409` (файл уже загружен), `422` (не удалось извлечь текст).

### 🔍 `POST /search`
Семантический поиск по загруженным документам.
* **Принимает:** JSON с полями `query` (текст запроса) и `top_k` (количество возвращаемых фрагментов).
* **Что делает:** Векторизует запрос через Ollama, сравнивает вектор запроса с векторами в базе (косинусное расстояние) и возвращает наиболее релевантные чанки.

## Настройка `.env`

Файл `.env` позволяет гибко управлять поведением системы без изменения кода:

* **Настройки загрузки:** 
  * `MAX_FILE_SIZE_MB` — максимальный размер загружаемого файла в мегабайтах.
* **База данных:** Параметры подключения (`DATABASE_*`), выбор индекса для pgvector (`INDEX_TYPE='hnsw'`).
* **Эмбеддинги:** 
  * `EMBEDDING_MODEL` — название модели в Ollama (по умолчанию `bge-m3`).
  * `EMBED_DIM` — размерность вектора (для bge-m3 это 1024).
  * `EMBED_DOC_PREFIX` / `EMBED_QUERY_PREFIX` — префиксы (нужны для некоторых моделей, например `nomic-embed-text`).
* **Чанкирование:** `CHUNK_SIZE` (размер куска текста) и `CHUNK_OVERLAP` (перекрытие).
* **Настройки поиска:** `TOP_K` (сколько чанков выдавать по умолчанию) и `SEARCH_MAX_DISTANCE` (порог отсечения нерелевантных результатов: от 0 до 1).

## Для разработчиков (Локальный запуск без Docker)

Если вы хотите доработать проект, вам понадобится [uv](https://github.com/astral-sh/uv).

1. Установите зависимости:

    ```bash
    uv sync --all-groups
    ```
2. Измените настройки хостов в .env
    
    ```.dotenv
    OLLAMA_HOST='http://localhost:11434'
    DATABASE_HOST='localhost'
    ```
3. Запустите docker-compose и соберите контейнеры БД и Ollama
    
    ```bash
    docker-compose up --build database ollama ollama-model-loader
    ```
4. Локально в проекте примените миграции после запуска контейнеров
    
    ```bash
    uv run alembic upgrade head
    ```
5. Запустите локальный сервер (при условии, что БД и Ollama уже запущены):
   
    ```bash
    uv run uvicorn app.main:app --reload
    ```
   или запустите файл main.py из вашей IDE
